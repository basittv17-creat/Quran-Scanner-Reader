## Findings and changes

- Decoder sampling already uses ceiling division in Long and power-of-two samples. It bounds the sampled camera JPEG edge at 1,500 and the gallery edge at 2,048. The gallery rechecks returned dimensions and releases superseded bitmaps. At four bytes per pixel, square images at those limits contain about 8.6 and 16 MiB of pixel payload respectively. These are calculations. Codec scratch space, higher precision pixels, stride, transforms, and the native OCR heap add their own costs.
- The JPEG path copies at most 32 MiB of compressed bytes before its bounds pass. Camera analysis caps pixel area at four million. Follow up with Work 01 on actual JPEG output checks, allocation failure recovery before the callback releases its scan claim, and whether avoiding the JPEG byte copy is supported on target devices. The gallery opens a provider stream separately for bounds, EXIF and decode. Its post-decode check cannot prevent allocation if the provider changes the stream between reads. Validate mutable provider behavior and low-memory recovery on device before choosing a bounded local staging strategy.
- OCR tries the original bitmap with the same page segmentation modes, score, confidence shortcut and text cap. It now prepares the normalized fallback only when the original attempts fail to trigger the existing shortcut. This avoids the normalization allocation and draw on that shortcut. If needed, normalization still uses the existing two-pass scale and color transform and releases temporary bitmaps on exceptional exits. Each read still verifies the extracted model and initializes its own native engine. Keeping the engine across reads would require a separate lifecycle and native-memory audit.
- Quality samples at most 56 × 56 positions with two adjacent comparisons each. Alpha is composited over white in the diagnostic only. Mean luma below 65 advises on lighting and a strong-edge share below 0.6% advises on detail. Strong edges have a luma difference of at least 22. The fixed adjacent-pixel offset makes the result resolution-dependent. Blank margins, sparse print, glare, noise, rules, and sampling alignment can distort it. Low light takes priority in the UI if both flags fire. These are advisory thresholds and have no effect on candidate scoring, matching, or recitation confirmation.
- Deterministic JVM cases cover exact sampling transitions, invalid bounds followed by a valid request, extreme dimensions, partial alpha, and exact edge thresholds. Decoder failures, EXIF transforms and bitmap allocation recovery require Android validation. Exercise corrupt and truncated imports or captures, then valid full-image scans. Confirm stale results never update the UI, the next scan runs, and allocations return toward baseline.

Log exact publisher, edition, printing type and ink colors, page/printing group, capture and split IDs, file SHA-256, and rights/reviewer approvals. Keep repeated captures of a page in the same split. Cover normal light, low light, glare, focus variation, and low-detail scenes. Keep synthetic runs separate. Use local files and offline devices.
2. Log the source commit, Android device model/OEM, ABI, API level and OS build, RAM class, camera ID, requested and actual resolution, JPEG size, sampled and transformed dimensions, OCR profile, full-image/crop state, and attempts completed. Pin the bundled and extracted Arabic model SHA-256 to `e3206d3dc87fd50c24a0fb9f01838615911d25168f4e64415244b67d2bb3e729`. Record native OCR dependency version and device thermal/battery state. Compare API 23 and at least two modern devices from different OEMs.
3. Separate first-use cold (fresh process and no extracted model), process cold (fresh process and verified extracted model present), and warm (same foreground process, repeat after two unscored warmups). A warm scan still initializes the engine. Use an authorized pre-existing device installation and local profiling facilities. Run at least 10 trials per cold condition and 30 warm trials per condition and device. Randomize with a recorded seed and keep JPEG bytes fixed for decoder/OCR comparisons. Record live capture separately with consistent lighting, distance and exposure. Record failures and cancellations with their stage and trial ID.
4. Use monotonic timestamps or local trace spans for capture, JPEG bounds and pixel decode, orientation/crop, quality diagnostics, model verification/extraction, engine initialization, fallback preprocessing, each variant's image transfer, native recognition and text extraction, cleanup, corpus load/matching, and result presentation to first rendered frame. The existing **OCR completed** UI duration measures the wall time inside the OCR pipeline before final engine disposal, including diagnostics and model work. It excludes JPEG decoding, matching and UI rendering. For inference only, measure the native recognition span independently. If only the text retrieval call can be timed, label it recognition and text retrieval. Record total capture-to-result time separately.
5. Report per-stage median and p95 (nearest rank), trial counts and failures by device, cold/warm condition, edition, and capture resolution. Sample process total PSS and Java/native heap before scanning, during repeat batches and after idle. Report peak sampled PSS and the sampling interval, and name any gaps in native allocation visibility. Capture process CPU time and wall time for the same batches. Record battery and thermal conditions, screen brightness, radios, and charging state. Compare a fixed-duration scripted repeated-scan batch to an equal-duration idle screen baseline on the same unplugged device. Record supported charge or energy counters, duration and repeat count. Mark unsupported counters as unavailable. Profile instrumented runs separately if the profiler materially changes timing.
6. Report raw OCR accuracy and candidate behavior using the existing dataset evaluator. Evaluate each advisory on held-out photographs against independently labeled lighting/readability conditions and report false positives and negatives by edition and capture resolution. Retain the existing thresholds until representative evidence supports a change.
